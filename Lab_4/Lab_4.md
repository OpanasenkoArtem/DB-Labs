# Лабораторна робота №4: Аналітичні SQL-запити

## Частина 1: Агрегація та Групування

### Запит 1. Загальний дохід магазину

**Мета:** Отримати фінансовий звіт про загальний обіг коштів у магазині.

```sql
SELECT SUM(amount) AS total_revenue
FROM Payment;
```

- **Як це працює:** Функція `SUM(amount)` підсумовує всі значення у стовпці `amount` таблиці `Payment`.
- **Результат:** Одне число, яке показує сумарний виторг за весь час.

---

### Запит 2. Статистика цін товарів

**Мета:** Проаналізувати цінову політику (найдешевший, найдорожчий та середній товар).

```sql
SELECT
    MIN(price) AS min_price,
    MAX(price) AS max_price,
    AVG(price) AS avg_price
FROM Product;
```

- **Як це працює:** Використовуються агрегатні функції `MIN` (мінімум), `MAX` (максимум) та `AVG` (середнє значення) для стовпця `price`.
- **Результат:** Зведений рядок із ціновими показниками асортименту.

---

### Запит 3. Кількість замовлень за статусом

**Мета:** Отримати зріз поточного стану замовлень у магазині.

```sql
SELECT
    status,
    COUNT(*) AS orders_count
FROM "order"
GROUP BY status
ORDER BY orders_count DESC;
```

- **Як це працює:** `GROUP BY status` групує замовлення за статусом, `COUNT(*)` рахує кількість у кожній групі.
- **Результат:** Таблиця зі статусами та відповідною кількістю замовлень.

## Частина 2: Об'єднання таблиць (JOIN)

### Запит 4. Деталізація замовлень із назвами товарів (INNER JOIN)

**Мета:** Отримати зрозумілий список позицій замовлень із назвами замість ID.

```sql
SELECT
    od.order_id,
    p.name AS product_name,
    od.quantity,
    od.price AS unit_price
FROM Order_details od
INNER JOIN Product p ON od.product_id = p.id;
```

- **Як це працює:** `INNER JOIN` залишає тільки ті рядки `Order_details`, де є відповідний товар у `Product`.
- **Результат:** Таблиця позицій замовлення з розшифровкою назв товарів.

---

### Запит 5. Клієнти та їх замовлення (LEFT JOIN)

**Мета:** Виявити всіх клієнтів, включаючи тих, хто ще не робив замовлень.

```sql
SELECT
    c.name AS client_name,
    c.email,
    o.id AS order_id,
    o.status,
    o.order_date
FROM Client c
LEFT JOIN "order" o ON c.id = o.client_id
ORDER BY c.name;
```

- **Як це працює:** `LEFT JOIN` повертає всіх клієнтів. Якщо у клієнта немає замовлень, у колонках замовлення буде `NULL`.
- **Результат:** Повний список клієнтів. `NULL` у полі `order_id` вказує на неактивного клієнта.

---

### Запит 6. Аудит категорій (RIGHT JOIN)

**Мета:** Знайти категорії, що існують у базі, але не мають прив'язаних товарів.

```sql
SELECT
    p.name AS product_name,
    c.name AS category_name
FROM Product p
RIGHT JOIN Category c ON p.category_id = c.id;
```

- **Як це працює:** `RIGHT JOIN` гарантує вивід усіх категорій (права таблиця). Товари приєднуються до них.
- **Результат:** Список категорій. Якщо `product_name` = `NULL` — категорія порожня.

## Частина 3: Підзапити

### Запит 7. Товари дорожчі за середню ціну

**Мета:** Виділити преміум-сегмент товарів.

```sql
SELECT name, price
FROM Product
WHERE price > (SELECT AVG(price) FROM Product)
ORDER BY price DESC;
```

- **Як це працює:** Підзапит `(SELECT AVG(price) FROM Product)` обчислює середню ціну по всьому каталогу. Основний запит фільтрує товари, ціна яких вища за це значення.
- **Результат:** Список товарів з ціною вище середньої.

---

### Запит 8. Персональний лічильник замовлень клієнта

**Мета:** Швидкий перегляд активності кожного клієнта без окремого групування.

```sql
SELECT
    c.name,
    c.email,
    (SELECT COUNT(*)
     FROM "order" o
     WHERE o.client_id = c.id) AS total_orders
FROM Client c;
```

- **Як це працює:** Для кожного рядка клієнта виконується окремий корельований підзапит, що рахує його замовлення в таблиці `"order"`.
- **Результат:** Список клієнтів з колонкою `total_orders`.

---

### Запит 9. Клієнти, що замовляли товари певної категорії (підзапит з IN)

**Мета:** Знайти клієнтів, які купили хоча б один товар із категорії «Electronics».

```sql
SELECT name, email
FROM Client
WHERE id IN (
    SELECT o.client_id
    FROM "order" o
    JOIN Order_details od ON o.id = od.order_id
    JOIN Product p ON od.product_id = p.id
    JOIN Category c ON p.category_id = c.id
    WHERE c.name = 'Electronics'
);
```

- **Як це працює:** Внутрішній запит формує список ID клієнтів, що купували електроніку. Зовнішній запит обирає імена та email клієнтів, чиї ID входять у цей список.
- **Результат:** Імена та контакти цільової групи клієнтів.

---

### Запит 10. Категорії з середньою ціною вище загальної (підзапит у HAVING)

**Мета:** Знайти категорії преміум-сегменту.

```sql
SELECT
    c.name AS category_name,
    ROUND(AVG(p.price), 2) AS avg_price
FROM Product p
JOIN Category c ON p.category_id = c.id
GROUP BY c.name
HAVING AVG(p.price) > (SELECT AVG(price) FROM Product)
ORDER BY avg_price DESC;
```

- **Як це працює:** Підзапит у `HAVING` обчислює загальну середню ціну по всіх товарах. Групи категорій, де середня ціна нижча за цей поріг, відкидаються.
- **Результат:** Категорії, чий середній ціновий рівень перевищує загальний по магазину.
